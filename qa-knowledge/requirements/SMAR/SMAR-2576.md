## Requirement Summary

SMAR-2576 standardizes QuickBooks invoice line-item descriptions generated from CP Desktop Billing Reports. Provider and Client invoices replace Village-style Client File and Date On/Date Off text with service-specific information and, for recurring services, the configured billing cycle and timing. The linked specification also defines unchanged Village mappings for regression.

The approved test page contains 55 source rows. Forty-five non-conflicting rows are normalized into 11 executable cases. Ten Hardware Rental rows are deferred because their descriptions omit the term/payment suffix required by the ticket-linked specification and the existing confirmed SMAR-2467 knowledge.

## Confirmed Scope

- CP Desktop **Settings → Reports → Billing Report**.
- Village, Provider, and Client Billing Report filters needed to exercise the supplied matrix.
- QuickBooks sandbox invoice Activity and Description for Monitoring, Telstra SIM, Voda SIM, Welfare Check, Establishment Fee, and Hardware Purchase.
- Provider/Client Monthly, Quarterly, Biannual, and Annual cycles in Advance and Arrears where recurring billing applies.
- Village Online/Offline date-description regression for applicable services.
- Correct billing-party, service, occurrence, and invoice-line association using privacy-safe synthetic data.

## Business Rules

1. Select the description template from Billing Type and Service Type.
2. Add Device Type, Billing Cycle, Billing Timing, and billing-status dates only where the confirmed template requires them.
3. Provider/Client descriptions must not reuse Village Client File, Village, Date On, or Date Off text.
4. Establishment Fee for Provider/Client has an empty Description while retaining Activity `ESTAB FEE`.
5. SIM Activity remains carrier-specific while its Provider/Client Description uses Device Type, Cycle, and Timing.
6. Existing confirmed Hardware Rental term/payment behavior is not replaced by the conflicting SMAR-2576 source rows.

## UI/UX Rules

- The Billing Report must identify the prepared billing occurrence before export.
- QuickBooks invoice-line Activity and Description are the primary observable results.
- Blank Establishment Fee Description must be distinguishable from a literal `N/A`, `~BLANK~`, whitespace-only value, or inherited previous text.

## API / Backend Impact

Jira identifies `GetBillingDesc` in `AccountingService` as the context-dependent description source. Exact endpoint, request/response schema, internal lookup structure, and error contract are not supplied and must not be invented in manual cases.

## Integration Impact

- CP Desktop Billing Report export creates the applicable QuickBooks invoice line.
- Activity and Description must match the selected Billing Type/Service Type context.
- Export evidence must remain associated with the correct billing party, Client File, service, and occurrence.
- Duplicate and cross-party outcomes are material QA risks even though retry mechanics are not specified.

## Permissions / Roles

Use an authorized non-production billing-report/export role. Exact permission names and the complete role matrix are not supplied.

## Background Jobs / Queues

No new job or queue behavior is confirmed. Internal export retry, deduplication, and failure-state contracts remain Open Questions.

## Audit / History / Logs

- Tester-accessible evidence: Billing Report row, export result, QuickBooks sandbox invoice and line.
- Use exposed export identifiers or timestamps to associate the report occurrence and QuickBooks line when available.
- Do not require an inaccessible internal log unless a failure or duplicate cannot be distinguished through the supported surfaces.

## Reports / Export Impact

The change applies to QuickBooks invoice lines generated from CP Desktop Billing Reports. Report source values must map to the exact Activity and Description template without modifying the billing service, status, dates, cycle, timing, rate, or unrelated report rows.

## Cross-Platform Sync Impact

No Mobile SOS, Mobile Carer, Portal Web, or CP Web presentation change is confirmed. CP Desktop and the QuickBooks sandbox must agree on the exported occurrence and final line values.

## Privacy / Sensitive Data Impact

- Use synthetic Client Files, Village names, billing parties, device types, dates, and QuickBooks customers.
- Evidence must not contain production client names, contact data, billing-account details, authentication data, or tenant-sensitive identifiers.
- Provider/Client descriptions must not expose the removed Client File or Village details.

## Test Data, Isolation, and Cleanup

- Prepare isolated Village, Provider, and Client Billing Report datasets using non-production QuickBooks customers.
- For Provider and Client recurring services, prepare all eight Cycle/Timing combinations: Monthly, Quarterly, Biannual, Annual × Advance, Arrears.
- Prepare separate Telstra and Voda SIM records so Activity mapping is observable.
- Record existing invoice/export counts before each export and avoid reusing an already-exported occurrence.
- Retain required audit/export evidence; remove only disposable unexported test data according to the environment cleanup process.

## Required Test Instrumentation

## Regression Risk

Shared `GetBillingDesc` logic affects all Village, Provider, and Client QuickBooks descriptions. Regression must cover every confirmed non-conflicting service template, carrier Activity, recurring Cycle/Timing combination, Online/Offline Village date rule, blank Establishment Fee behavior, billing-party isolation, and protection against duplicate or unrelated lines. Hardware Rental term/payment coverage remains in SMAR-2467 until GAP-01 is resolved.

## Confirmed Decisions

- D1 / DEC-029 — Provider and Client non-Hardware-Rental QuickBooks descriptions use the approved service-specific templates and exclude legacy Village client/date details; Village mappings remain regression coverage.
- DEC-015 — Hardware Rental descriptions retain the confirmed term/payment sequence and are not replaced by the conflicting SMAR-2576 source rows.
