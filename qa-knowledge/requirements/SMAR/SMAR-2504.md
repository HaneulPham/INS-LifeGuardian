## Requirement Summary

SMAR-2504 adds a CP Web validation rule to **Work Orders → Invoice Management → Raptor DVA Submissions**. When a user selects invoices and runs **Validate Invoices Before Export**, a selected invoice with Prior Approval Number `N/A`, `N.A`, `NA`, or whitespace only fails with the exact Errors-column message `Prior App Number must be blank or a valid number.` A genuinely blank value does not trigger this error. Validation applies only to selected invoices and does not change invoice status or automatically modify the stored Prior Approval Number.

## Confirmed Scope

- CP Web Raptor DVA Submissions grid.
- Selected-record execution of **Validate Invoices Before Export**.
- Exact invalid datasets `N/A`, `N.A`, `NA`, and whitespace only.
- Exact Errors-column message for invalid data.
- Genuinely blank positive boundary.
- Selected-versus-unselected invoice isolation.
- Correction to a valid value, persistence after reopen, and revalidation.
- Invoice status and Prior Approval Number non-mutation during validation.

## Out of Scope

- Work Order or Invoice create/update save-time validation in CP Web and APIs; covered by SMAR-2528.
- DVA rental-date calculation, XML mapping, and export idempotency; covered by SMAR-2633.
- A fixed valid Prior Approval Number format beyond the source value `123456`.
- CP Desktop, Portal Web, Mobile SOS, and Mobile Carer behavior; no change is stated.

## Business Rules

1. Validate only invoices selected for the current **Validate Invoices Before Export** action.
2. Reject the confirmed exact invalid values and show the ticket-defined message in each affected selected row.
3. Distinguish a genuinely blank value from whitespace-only input.
4. Validation is non-mutating: it does not clear the field or change invoice status.
5. A corrected valid value must be persisted before the invoice is revalidated.

## UI/UX Rules

- The validation result is observable in the selected invoice's **Errors** column.
- The exact invalid-data message is `Prior App Number must be blank or a valid number.`
- A valid corrected invoice with no other errors displays `The invoice has no validation errors.`
- An unselected invoice does not receive a new Errors-column result from another invoice's validation action.

## Validation Rules

- Confirmed invalid values: exact `N/A`, `N.A`, `NA`, and whitespace only.
- Confirmed allowed boundary: genuinely blank.
- Lowercase or alternate-separator normalization and `None` batch handling remain Open Questions.

## Confirmed Decisions

- D1 / DEC-027 — Raptor DVA pre-export validation rejects the four confirmed invalid values only for selected invoices, uses the exact ticket message, and does not mutate invoice status or stored Prior Approval Number.
