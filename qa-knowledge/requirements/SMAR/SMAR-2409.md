## Requirement Summary

Align CP Stock Type and Tag descriptions with the Device Type terminology by removing the word `Dialler` from the specified Stock Levels, transaction, and Service Request view/edit surfaces. Preserve the exact name `SmartLink Under Dialler`. The ticket defines a display-description change and does not confirm changes to identifiers, stock quantities, Service Request relationships, reports, integrations, or historical data storage.

## Confirmed Scope

- CP Stock Levels Stock Type descriptions.
- Stock transaction action surfaces named by the supplied Confluence cases: Create Order, Receive Order, Dispatch Stock, Pending Return, Receive Stock, Stock Take, and Adjustment.
- Stock Levels Transaction History descriptions.
- Service Request view surfaces showing Stock Types and Tags.
- Service Request edit surfaces showing Stock Type and Tag descriptions.
- Exact preservation of `SmartLink Under Dialler` wherever the confirmed affected Stock Type or Tag sources render it.

## Out of Scope

- No report or export behaviour is confirmed; source TC#7 remains deferred.
- Mobile SOS, Mobile Carer, Portal Web, and CP Web are not identified as affected platforms.
- No API, database schema, notification, alert, billing, QuickBooks, queue, job, or external-provider change is confirmed.
- No requirement changes Stock Type, Tag, Device Type, or Asset Type identifiers, relationships, stock quantities, or Service Request workflow state.

## Business Rules

1. Affected Stock Type descriptions on the confirmed stock and Service Request surfaces do not contain the word `Dialler`.
2. Affected Tag descriptions on the confirmed Service Request surfaces do not contain the word `Dialler`.
3. `SmartLink Under Dialler` remains exactly `SmartLink Under Dialler` and is not shortened by the description update.
4. Report and Asset Type expectations must not be treated as confirmed until GAP-01 and GAP-02 are resolved.

## UI/UX Rules

- The renamed descriptions are visible in Stock Levels, the named transaction action surfaces, Transaction History, and Service Request view/edit surfaces.
- Refreshing or reopening a confirmed affected surface continues to show the same expected description.
- The ticket does not specify list order, search aliases, validation messages, or formatting beyond removal or preservation of the stated word.

## Validation Rules

- Compare the complete displayed description, not only a truncated grid value or tooltip fragment.
- Test every known affected source description supplied by the environment mapping.
- Verify the protected exception by exact text comparison.
- Observation-only and cancelled-dialog tests must not create a stock transaction or persist a Service Request edit.
