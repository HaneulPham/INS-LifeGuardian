## Deferred Scenarios

- Independent API/backend rejection of invalid Type conversions and Billing/Dispatch combinations requires confirmed endpoint and response contracts.
- Exact ordering and names of all non-Dispatch statuses remain governed by the current workflow and are not hardcoded by this suite.

## Requires Test Instrumentation

- Developer-supported API logs or persisted-record evidence are required only if UI/list/reopen evidence is insufficient to prove backend enforcement, Item relationship cleanup, or audit-event creation.

## Test Data and Cleanup

- Use isolated non-production Client Files, unique request descriptions, and distinct Items without client-sensitive content.
- Record request identifiers and counts before create/conversion cases.
- Roll back Community Centre and disposable request data when permitted; do not remove required audit evidence or unrelated Service Requests.
