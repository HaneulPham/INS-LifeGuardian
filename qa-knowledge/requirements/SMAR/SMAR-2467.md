## Requirement Summary

SMAR-2467 replaces manual Hardware Rental term management with a controlled CP Desktop Billing workflow. Hardware Rental uses a required 12- or 24-month Rental Term, derives and persists End Date, remains Online through that End Date, and is taken Offline after the date completes. Eligible occurrences appear in Billing Reports and export to QuickBooks with standardized Hardware Rental descriptions and payment sequence text.

The change is conditional to Hardware Rental. Existing billing grids retain the End Date column, non-Hardware services retain their existing date behavior, and the Device Information rental labels are prefixed with `Village` to distinguish them from the billing Rental Term.

## Confirmed Scope

- CP Desktop Client File Billing and Device Information.
- Billing API persistence and rejection behavior for Hardware Rental and non-Hardware services.
- Calendar calculation and persistence for 12- and 24-month terms.
- EventBridge automatic-Offline schedule creation, replacement, cancellation, execution and duplicate prevention.
- Village, Provider and Client Billing Reports.
- QuickBooks sandbox export descriptions and payment sequence.
- Role restrictions, client/tenant isolation, reopen persistence, audit and duplicate prevention.

## Business, UI and Validation Rules

- Hardware Rental alone replaces editable End Date with Rental Term in the status dialog.
- Rental Term is blank until selected and permits only 12 Months or 24 Months.
- Online Hardware Rental without a valid term is rejected with no partial Start Date, End Date, status, schedule or duplicate record.
- Cancel preserves the previously saved status, Start Date, Rental Term and End Date.
- The billing grid continues to label the persisted date as End Date.
- Monitoring and other non-Hardware services do not display Rental Term and retain existing End Date behavior.
- Device Information uses the exact Village-prefixed rental labels without stale or cross-client values.

## API / Backend Impact

- The Billing API stores the Hardware Rental status, Start Date, term representation and derived End Date as one consistent update.
- Unsupported, missing, malformed, unauthorized, stale or cross-tenant updates persist no partial state and create no duplicate service.
- A submitted End Date for an Online non-Hardware service is not persisted.
- Exact route, HTTP method, response status/schema, concurrency token and term representation remain Open Questions and must be captured from the implemented contract.

## Background Jobs / Queues

- One active EventBridge schedule is associated with each Online Hardware Rental billing instance.
- Updating Start Date or Rental Term leaves only the current schedule capable of execution.
- Manual Offline or removal cancels the pending schedule.
- Automatic processing occurs after the End Date completes in the configured business time zone, persists one Offline transition and records `System` as actor.
- Schedule, handler, retry and failure assertions require developer-supported AWS/application evidence where CP Desktop does not expose them.

## Reports / Export Impact

- Online Hardware Rental is eligible for the applicable Billing Report, including its final billable period.
- Village uses the approved client-file/device/term description; Provider and Client use device/cycle/timing/term.
- QuickBooks Activity is `HARDWARE RENTAL`.
- Term text uses `12 Month Term` or `24 Month Term`; payment text progresses from `Pmt 1 of Y` to the final `Pmt Y of Y`.
- Report regeneration and export retry do not create duplicate rows, occurrences, invoices, invoice lines or export records.

## Permissions / Roles

- A billing-edit user can configure Hardware Rental.
- A restricted user cannot change status, Start Date or Rental Term through the visible UI or another exposed edit path.
- Billing Report/export permissions and exact backend authorization claims follow the implemented permission model; the full role matrix was not supplied.

## Audit / History / Logs

- Manual changes record the acting user, timestamp and affected values when the implemented audit surface is available.
- Automatic Offline records `System` and is traceable to the schedule/handler execution.
- QuickBooks export evidence identifies the billing occurrence, invoice/line and final export state.
- Logs and screenshots must use privacy-safe identifiers and contain no unnecessary client, contact, authentication or tenant-sensitive data.

## Test Data, Isolation, and Cleanup

- Use isolated non-production Client Files, devices, billing parties and QuickBooks sandbox customers for 12- and 24-month terms.
- Use known date matrices for normal anniversaries, 29 February, month end and End Date boundaries.
- Isolate Village, Provider and Client exports so one case cannot invoice another billing party.
- After execution, remove pending schedules and unexported test billing records while retaining required audit/export evidence; do not delete unrelated or historical records.

## Required Test Instrumentation

- Tester-accessible: CP Desktop state, reopened values, Billing Reports, QuickBooks sandbox invoice lines and any exposed audit/export records.
- Developer-supported: exact Billing API request/response, persisted term/End Date, EventBridge schedule name/target, handler timestamps, retries, DLQ behavior and automatic actor evidence.
- Operations-supported: provider or AWS console evidence where the test environment does not expose it to QA.
