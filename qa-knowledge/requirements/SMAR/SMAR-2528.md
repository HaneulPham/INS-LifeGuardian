## Requirement Summary

SMAR-2528 prevents invalid DVA Prior Approval Number values from being saved on Work Orders and Invoices. The prohibited values are `N/A`, `NA`, and `None`, compared case-insensitively. Whitespace-only supplied values are rejected, while a genuinely empty optional value remains allowed. Leading and trailing whitespace is trimmed before persistence. Validation applies in CP Web and the API.

The API rejection contract is confirmed as HTTP `400 Bad Request` with `Error = "bad_request"` and `ErrorDescription = "'Dva Presc On' must be a valid value or blank"`.

The final CP Web presentation remains unresolved because the current Jira description, approved Confluence cases, and latest Jira comment do not agree.

## Business Rules

1. Compare prohibited values case-insensitively after applying the supported leading/trailing whitespace normalization.
2. Reject only normalized exact prohibited values; do not reject a valid value merely because it contains `NA`, `N/A`, or `None` as a substring.
3. Treat a truly empty optional value separately from a supplied whitespace-only value.
4. A rejected create or update does not persist the Prior Approval Number or unrelated request changes.
5. A historical invalid value is not silently changed on view; it must be corrected or cleared before an update can persist.

## Validation Rules

- Invalid normalized exact values: `N/A`, `NA`, and `None`.
- Comparison is case-insensitive.
- Whitespace-only supplied input is invalid.
- An empty optional field is allowed.
- Leading and trailing whitespace is removed before persistence.
- Internal characters and variable supported free-text formats remain unchanged.
- Invalid submissions cause no partial create or update.
