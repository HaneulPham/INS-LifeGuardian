# SMAR-2537 - New Service Request Steps for Peripherals

## Requirement Summary

Add **Generate Medi-Alarm** and **Listen for Alarm** steps for eligible peripherals in **Administration / Settings -> Device Setup Steps** and the related Service Request Progress workflow.

This note captures Group 1 test design for **Administration / Settings -> Device Setup Steps** and Group 2 test design for **Service Request Progress Tab**.

Group 3 **Listen for Alarm** runtime matching cases are saved separately in `SMAR-2537-group-3-listen-for-alarm.md` for readability.

## Confirmed Scope

- **PIR** is unsupported and must not expose **Generate Medi-Alarm** or **Listen for Alarm**.
- The step label in **Device Setup Steps** is **Generate Medi-Alarm**.
- The Service Request Progress popup/action may show **New Medi Alarm Device** and uses **OK** / **CANCEL** actions.
- CAMS medi-alarm device types should create/show under **Medi-Alarm Devices**.
- INS medi-alarm device types should create/show under **Home Security Devices**.
- Backend verification source for created medi-alarm details is `GET /lg/medialarmdevice/v2/{{uuid}}`.

## Eligible Peripherals

- `BrooksSmoke240v`
- `BrooksSmoke240vLithium`
- `LSeriesSmoke240v`
- `SmartlinkSmoke240v`
- `Smoke9v`
- `LSeriesTransmitter`
- `LSeriesTransmitterF1`
- `SmartlinkTransmitter`
- `LSeriesFallSensor`
- `SmartlinkFallSensor`
- `ChiptechPearlFallSensor`
- `LSeriesCallPoint`
- `SmartlinkCallPoint`
- `MiaPendant`
- `LSeriesSmokeTransmitter`
- `SmartlinkSmokeTransmitter`
- `ChiptechPearlNeckTransmitter`
- `ChiptechPearlWatchTransmitter`

## Observed Error Dialog Evidence

- Duplicate **Listen for Alarm** can show **Invalid Step Order** with message equivalent to `Only one Listen for Alarm step is allowed.`
- Invalid ordering can show **Invalid Step Order** with message equivalent to `Listen for Alarm must come AFTER Assign to Client File.`
- Invalid deletion can show **Cannot Delete Step** with message equivalent to `Can't delete Assign to Client File. Remove the following steps first: Listen for Alarm.`

Exact dialog copy can be flexible where implementation lists the direct or final dependent step.

## Needs Confirmation

- Exact response field names from `GET /lg/medialarmdevice/v2/{{uuid}}` for file ID, owner/client ID, parent/main device ID, and medi-alarm device type.
- Whether SMAR-2537 applies only to new Service Requests or also existing unstarted/snapshotted requests.
- Whether duplicate-looking Type labels represent distinct backend values or should be displayed as unique labels.
- Exact validation text for missing **Type** on **Generate Medi-Alarm**.
