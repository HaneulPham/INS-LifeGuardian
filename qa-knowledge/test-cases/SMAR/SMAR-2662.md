## Duplicate Review

- Existing related test cases checked: SMAR-2638, SMAR-2650, and SMAR-2658.
- Duplicate primary outcomes found: No.
- Overlap retained: Valid OAuth and authentication-rejection regression is retained because SMAR-2662 verifies cryptographic JWT integrity in shared LifeGuardServices paths, while the related suites verify distinct HMAC or legacy-dispatcher authentication-selection rules.
- Group 1 remains authoritative for detailed signature, algorithm, key, and `kid` manipulation; later groups verify consumer-specific enforcement without repeating the full matrix.
- Approved IDs and 49 distinct primary verification goals are preserved.

### Deferred Scenarios

- Exact algorithm names, key identifiers, token carriers, accepted status codes, error-schema fields, and runtime log fields remain deferred until deployed contract evidence is supplied where applicable.

### Requires Test Instrumentation

- Correlated signature-validation outcome and protected-handler non-entry evidence require tester-accessible security logs or development/operations-supported telemetry.

### Test Data and Cleanup

- Use synthetic isolated users, devices, groups, codes, and controlled STAG tokens. Redact complete token values and signing material. Roll back reversible profile/password changes and remove only disposable records while preserving required sanitized audit/security evidence.
