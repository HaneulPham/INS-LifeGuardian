## Requirement Summary

Correct Document Field History generated by the SHM Old Backend `CreateClientFileRequest` and `UpdateClientFileRequest`. `EditedBy` is nullable and defaults to `IPD` when omitted, null, or blank. Explicit supported platform values remain unchanged and display with their defined labels. Create requests also log the confirmed Client File fields and Medication name/dosage format.

## Confirmed Scope

- SHM Old Backend `CreateClientFileRequest` and `UpdateClientFileRequest` through the dispatcher.
- Omitted, null, blank, and explicitly supplied `EditedBy` values.
- Supported platform values: `ControlPanel`, `Portal`, `MobileApp`, `CarerApp`, and `IPD`.
- CP Desktop Document Change Log and approved Document Field History API evidence.
- Create-time history for the confirmed File fields and Client Medication.
- Update-time history for changed File fields.

## Out of Scope

- New Mobile, Carer, Portal, or CP feature behavior; these are existing callers/display consumers.
- New notification, alarm, billing, report, export, queue, or scheduled-job behavior.
- Authentication changes to the SHM dispatcher.
- Changing Document Field History behavior for Village, Contact, Procedure, Device Unallocation, or unrelated Client fields.
- A new error contract for unsupported enum values; the approved ticket-specific response is retained.

## Business Rules

1. Missing `EditedBy` must not be interpreted as `ControlPanel`; it resolves to `IPD` for both target request classes.
2. An explicit valid value takes precedence over the default.
3. Platform display mapping is `ControlPanel` → `Control Panel`, `Portal` → `Portal`, `MobileApp` → `Mobile App`, `CarerApp` → `Carer App`, and `IPD` → `IPD`.
4. A created File-field history entry has blank/null Old Value, the submitted New Value, and no Source Field Name.
5. A created Medication history entry uses the medication name as Source Field Name and dosage as New Value.
6. An updated File-field history entry retains the exact previous and new values.
7. One accepted request creates one intended Client File/update and one history outcome per changed supported field.

## UI/UX Rules

- CP Desktop Document Change Log displays the resolved platform label for the same synthetic Client File and request.
- File and Medication history is associated with the correct Client/File and shows the confirmed old/new/source-field values.
- No change to Document Change Log navigation, filtering, or layout is specified.

## Validation Rules

- Omitted, JSON `null`, and empty-string `EditedBy` are accepted defaulting variants.
- The five defined enum values are accepted and preserved.
- An unsupported value such as `InvalidPlatform` returns the approved HTTP 500 response.
- Rejected input must not create a partial Client File, mutate an existing File, or create accepted history.

## API / Backend Impact

- Endpoint: `POST {{shm_domain}}/api/dispatcher` using the applicable request class.
- `CreateClientFileRequest` gains nullable `EditedBy`; `UpdateClientFileRequest.EditedBy` becomes nullable.
- Accepted requests return HTTP 200 according to the approved source suite.
- Invalid `EditedBy` returns HTTP 500; the exact error body and headers are not supplied.
- Exact request-property names for every File field, authentication headers, internal persistence objects, and internal log fields are not stored.

## Integration Impact

- Existing SOS/Mobile, Carer, Portal, CP, IPD, and Postman/API callers can provide a supported `EditedBy` value.
- CP Desktop and the Document Field History API are observable consumers of the generated history.
- No new external provider integration is confirmed.

## Permissions / Roles

- Use existing authorized SHM API credentials and an authorized CP Desktop role that can view Document Change Log.
- No new role, permission, tenant, or client-isolation contract is introduced.
- Credentials and tenant identifiers must remain in protected test configuration and never enter stored evidence.

## Background Jobs / Queues

None.

## Audit / History / Logs

- Document Field History is the primary feature outcome, not optional internal evidence.
- Tester-accessible evidence may be collected from CP Desktop Document Change Log or the approved history GET API.
- Relevant observable properties include source identity, platform, source field, Source Field Name, Old Value, New Value, updater, and timestamp where returned.
- R6 covers the confirmed File fields: File Name; File Group/Village; File Mobile Phone; File Home Phone; Notify Village in an Emergency; Free Trial Client; File Address; File Security Code; File Security Key Holder Access Code; File Specific Actions Required; and File General Notes.
- Direct datastore or internal logging evidence is unnecessary when the complete observable history is available.

## Reports / Export Impact

None.

## Cross-Platform Sync Impact

- Explicit platform values supplied by existing callers must resolve to the same stored and displayed platform.
- The detailed suite exercises the shared SHM API directly; application-specific creation/update workflows are targeted regression rather than new functionality.

## Privacy / Sensitive Data Impact

- Client File and Medication history can contain personal, contact, security, and health information.
- Use synthetic non-production File/Client values and synthetic medication names/dosages.
- Redact identifiers and values in screenshots, logs, request exports, and API evidence.
- Verify correct record association without exposing another client or tenant.

## Test Data, Isolation, and Cleanup

- Use unique disposable Client Files for Create matrices and one isolated reversible Client File for Update matrices.
- Record baseline File values and history counts before every rejected or update scenario.
- Keep credentials outside requests stored as evidence.
- Remove only disposable Client Files through supported actions and preserve required audit evidence according to environment policy.
- Restore reusable update values after execution when permitted without deleting required history.

## Required Test Instrumentation

- Protected authorized SHM dispatcher request configuration.
- Approved Create/Update payload/property mapping for every File field in R6.
- CP Desktop Document Change Log or authorized history API access for the created/updated Client/File.
- Sanitized request/response and history correlation using synthetic identifiers.

## Regression Risk

The shared `EditedBy` enum/default and Document Field History creation logic can misattribute changes from IPD, Mobile, Carer, Portal, or Control Panel callers; incomplete Create logging can omit Client File audit evidence or misrepresent Medication. Regression coverage is recorded in the regression map.
