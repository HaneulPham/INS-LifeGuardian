## Requirement Summary

CP Desktop Client Height and Weight fields must accept whole numbers and values with one decimal place in Client Medical Details and Nursing Review. Excess typed precision and negative values are prevented, zero and blank remain valid distinct states, saved decimal values retain their decimal component, and Nursing Review remains synchronized with the Client properties. Equivalent backend validation and Document Field History recording are confirmed, although the exact backend contract is not supplied.

## Confirmed Scope

- CP Desktop Client File → Edit Client File → Client Details → Client → Medical Details.
- CP Desktop Client File → Client → Nursing Review → Add Nursing Review.
- Client File viewing display for Height and Weight.
- Whole-number, one-decimal, excess-precision, negative, zero, blank, update, reopen, and new-session behavior.
- Client-property synchronization through Nursing Review.
- Document Field History old/new-value recording.
- Equivalent backend validation, subject to exact contract and evidence availability.

## Out of Scope

- CP Web and Mobile are not included by user decision Q4-A.
- Portal does not expose the Height or Weight fields; one low-priority absence regression case is retained.
- General malformed-input behavior beyond the confirmed negative and precision rules is deferred until exact datasets and expected outcomes are supplied.
- Reports, exports, notifications, alerts, billing, jobs, and queues are not identified as affected.

## Business Rules

1. Whole numbers and values with exactly one decimal digit are valid.
2. A second typed decimal digit is not accepted and must not be rounded into another value.
3. Pasted excess precision keeps the valid one-decimal prefix and prevents remaining digits.
4. Negative values are not accepted.
5. Numeric zero and blank/null are both valid but must remain distinguishable.
6. Saving Nursing Review Height or Weight updates the corresponding Client property.

## UI/UX Rules

- Client Medical Details and Nursing Review use the same input restrictions.
- Decimal values such as `70.5` display with their decimal component.
- A whole value may display as `70` or `70.0`; zero may display as `0` or `0.0`.
- Blank values remain blank and do not display a previous value or numeric default.

## Validation Rules

- Typed `175.55` and `70.55` stop at no more than one decimal place.
- Pasted `175.555` and `70.555` result in `175.5` and `70.5`, not the full input and not rounded values.
- Negative numeric values cannot be entered or persisted.
- Invalid input in one measurement must not change the other measurement or unrelated Client fields.
- Backend validation must reject negative and excess-precision values without partial persistence.

## API / Backend Impact

## Integration Impact

- Nursing Review and Client Medical Details consume the same current Client Height and Weight properties.
- Saved Client values are observable after reopen and in a new CP Desktop session.
- Document Field History records measurement changes.
- No other integration behavior is confirmed.

## Permissions / Roles

Stored cases require an authorized CP Desktop user who can edit Client Medical Details, add Nursing Reviews, and, for audit coverage, view Document Field History. Unauthorized-role behavior is not specified by SMAR-2325.

## Audit / History / Logs

Document Field History records separate Height and Weight changes with the correct Client, actor/time where the existing screen exposes them, and accurate old and new numeric values. Exact internal log or database contracts are not supplied.

## Reports / Export Impact

None confirmed.

## Cross-Platform Sync Impact

CP Desktop Nursing Review and Client Medical Details must converge on the same current Client Height and Weight values. Portal, CP Web, and Mobile synchronization are out of scope.

## Privacy / Sensitive Data Impact

Height and Weight are client health data. Testing must use isolated non-production Client records and evidence must avoid unnecessary personal, medical, contact, authentication, or tenant details.

## Test Data, Isolation, and Cleanup

- Restore the baseline after testing unless the environment requires retaining the final state for audit evidence.
- Preserve required Document Field History evidence while avoiding real client identifiers in screenshots or exported artifacts.
