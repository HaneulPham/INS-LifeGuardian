## Requirement Summary

Add `InteliCare Dialler` as a distinct Control Panel device, asset, stock, billing, and report identity. Generated assets use the exact ten-character `IN########` barcode sequence and generated devices use an `I`-prefixed Device Code. InteliCare is CAMS-connected and follows the approved LGX runtime behavior for alarms, fixed SIP, HangUp DTMF, SMS/device commands, power/battery, reboot, WiFi/SIP configuration, and peripherals. It supports the confirmed Service Request creation/assignment, SIM/Jasper, device lifecycle, billing, report, history, and QuickBooks workflows while remaining isolated from LGX and other devices.

## Confirmed Scope

- CP Desktop Asset Management, Stock Levels, Settings, Devices, Service Requests, Client File device assignment, Billing, Billing History, and Reports.
- Application/WCF Server, Alarm Receiver, Mobile Host, and SMS Host recognition of the compiled InteliCare enum/message value.
- CAMS alarms, device actions, peripherals, SIM/Jasper synchronization, and privacy-safe provider evidence.
- Billing Report and QuickBooks test integration using the confirmed Device Type description templates.
- Persistence, isolation, duplicate prevention, controlled concurrency, reload/reopen, and existing-device regression represented by Groups 1–7.

## Out of Scope

- Automatic migration or reclassification of existing LGX records; only new creation or an authorized Change Device Type workflow changes classification.
- A separate Jasper provider Device Type label; approved evidence requires the correct SIM/device relationship, ICCID, and line number.
- Mixed-version deployment and rollback execution beyond the confirmed code-before-Raven ordering.
- Production alarms, real client contact details, live SMS recipients, live device commands, live billing, or production QuickBooks records.

## Business Rules

1. InteliCare is functionally LGX/CAMS at runtime but remains a distinct INS catalogue and reporting identity.
2. `IN00000001` is the first barcode when `LastBarcodeId = 0`; each next accepted generation uses the next unique eight-digit numeric suffix.
3. An accepted create, stock action, alarm, command, SIM update, or billing/export action produces one intended outcome and does not change another device, Client File, Stock Type, or billing scope.
4. For SMAR-2700, Return Received moves quantity from Pending Return to In Stock without changing Total or Available when Allocated is unchanged. This is ticket-specific confirmed behavior and does not silently replace DEC-021 as a universal Stock rule.

## UI/UX Rules

- `InteliCare Dialler` appears exactly once with that spelling on applicable selectors, filters, details, reports, and configuration screens.
- Reopen and refresh retain the selected/persisted identity, identifiers, relationships, status, and values.
- Unsupported enum/deserialization errors and blank/duplicate catalogue entries are not displayed.

## Validation Rules

- Rejected asset or stock submissions create no partial record, duplicate identifier, transaction, or unrelated change.
- Existing validation and permission rules apply to InteliCare without bypass through another screen or Device Type selector.
- Identifier, relationship, and client isolation checks use synthetic non-production data.
