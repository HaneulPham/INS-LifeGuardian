## Requirement Summary

SMAR-2633 corrects DVA rental invoices when the Work Order Install Date and the Prior Approval date recorded as Presc On fall on different effective dates. CP Web must calculate and persist the invoice Rental Start Date when the invoice is generated. DVA validation and XML export must then use the persisted invoice values instead of recalculating dates from the Work Order.

The canonical calculation is:

`Rental Start Date = StartOfMonth(Max(Install Date, Presc On))`

The generated Rental End Date is the last calendar day of the generated Rental Start Date month. The change prevents invoices from passing internal validation with dates that DVA later rejects and gives users a supported correction path for Pending and Rejected invoices.

## Confirmed Scope

- CP Web Work Order invoice generation for DVA rental items.
- Raptor → DVA Submissions invoice review, validation, export, correction, and resubmission.
- Persisted Rental Start Date and Rental End Date.
- Rental Start Period Date and Rental End Period Date as protected period values.
- IVL027 comparison of Rental Start Period Date against Rental Start Date.
- DVA XML mapping of persisted invoice dates.
- Pending and Rejected invoice editability.
- Single-invoice and mixed-batch validation.
- Duplicate-export prevention.
- Regression protection for Buy and Recycle purchase types.

## Out of Scope

- Changing Work Order Install Date or Presc On during invoice-date editing.
- Editing Rental Start Period Date or Rental End Period Date.
- Applying rental-only calculations or IVL027 to Buy or Recycle invoices.
- Mobile SOS, Mobile Carer, Portal Web, CP Desktop, FCM, SMS, email, Twilio, or QuickBooks behaviour.
- Defining new role permissions, API endpoints, queue names, or audit-log formats.

## Business Rules

1. When a DVA rental invoice is generated, select the later of Work Order Install Date and Presc On.
2. Normalize the selected date to the first calendar day of its month and persist it as Rental Start Date.
3. Generate Rental End Date as the final calendar day of the Rental Start Date month.
4. Perform the calculation during invoice generation, not during XML export.
5. Preserve the generated Rental Start Date for later invoice periods unless a permitted user edits the invoice.
6. Updating Presc On after an historical invoice is created must not recalculate that historical invoice; the updated value applies to a newly generated invoice.
7. Work Order Install Date and Presc On remain unchanged by invoice generation, invoice-date editing, validation, and export.
8. DVA XML uses the saved invoice dates.
9. Buy and Recycle invoices retain their existing non-rental behaviour.

## UI/UX Rules

- Rental Start Date and Rental End Date are editable only when invoice status is Pending or Rejected.
- The fields are read-only for every other invoice status.
- Rental Start Period Date and Rental End Period Date remain read-only in all statuses.
- Invalid date edits must keep the invoice open for correction, identify the affected field, and must not show a save-confirmation state.
- A failed IVL027 invoice remains available for correction and revalidation.
- Mixed-batch validation displays the IVL027 error only against the invalid invoice row.

## Validation Rules

- Rental Start Date must be the first day of its calendar month.
- Rental End Date must be the last day of its calendar month, including 28 February in a non-leap year, 29 February in a leap year, and the correct final day for 30- and 31-day months.
- Failed boundary validation must persist neither invalid value nor a partial update.
- IVL027 fails when Rental Start Period Date is before Rental Start Date.
- The exact IVL027 message is: `Rental Period Start date is before the Rental Start date.`
- IVL027 passes when Rental Start Period Date equals or is later than Rental Start Date.
- Validation reads persisted invoice values and ignores unsaved edits.
- Repeated validation does not create duplicate records or alter invoice data.

## API / Backend Impact

No endpoint or database-table names were verified. Confirmed backend behaviour is limited to:

- Persist the calculated rental dates on the generated invoice.
- Persist valid manual edits only on the selected invoice.
- Reject invalid edits without false persistence.
- Read persisted invoice dates for IVL027 and XML export.
- Keep Work Order source dates and unrelated invoices unchanged.
- Prevent duplicate invoice/export processing covered by the approved cases.

## Integration Impact

- Persisted invoice Rental Start Date maps to DVA XML `HireStartDate`.
- Persisted invoice Rental Start Period Date maps to DVA XML `HirePrdStartDate`.
- Export must not recalculate or overwrite invoice dates from the Work Order.
- An invoice that fails IVL027 creates no new DVA XML export or submission record.
- Mixed-batch export includes only a newly selected set of passing invoices.
- Rejected invoices may be corrected, revalidated, and exported without creating a duplicate invoice.
- No FCM, SMS, email, Twilio, or QuickBooks integration is triggered by this date-calculation change.

## Permissions / Roles

- Status-based editability is Confirmed: Pending and Rejected are editable; all other statuses are read-only.
- The exact user-role or permission matrix is an Open Question.

## Background Jobs / Queues

The exact queue or job implementation could not be verified. Approved observable behaviour requires no XML, export, queue, or DVA submission for an invoice that remains invalid under IVL027.

## Audit / History / Logs

The exact audit-history and logging requirements are Open Questions. Historical invoice values and export history must remain distinguishable from new invoice and export attempts.

## Reports / Export Impact

- DVA export uses saved invoice dates.
- A failed validation must not expose an older XML file as the current export.
- A repeated export attempt must not create a second DVA submission or export-history record.
- Re-download, when supported, returns the existing artifact without creating a new submission.

## Cross-Platform Sync Impact

None. The approved requirement and cases cover CP Web and DVA export only.
