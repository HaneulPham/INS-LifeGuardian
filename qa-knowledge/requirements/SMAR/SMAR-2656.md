## Requirement Summary

The legacy SmartHome dispatcher must make all 33 request classes listed in SMAR-2656 inaccessible. Each resolvable deprecated request returns the standard exact `404 Not Found` contract before its handler, business validation, persistence, alarm processing, notification processing, or other downstream work begins. Authentication does not override deprecation: valid HMAC, applicable OAuth, missing credentials, invalid credentials, and both credential types together remain rejected.

`EscalateAlarmRequest` and `TakeAlarmRequest` must be blocked consistently in both the SmartHome and SmartHome Alarm services. The shared deprecation mechanism must not classify supported requests as deprecated or break current Portal, CP Web, Mobile, Carer App, IPD, AWS, alarm, or notification workflows that use active requests.

## Business Rules

1. Every resolvable request in the 33-class inventory returns exact `404 Not Found`.
2. The standard 404 response does not disclose whether credentials, identifiers, records, or business fields are valid.
3. Deprecation rejection precedes handler execution and handler-level validation.
4. Valid HMAC or OAuth cannot reactivate a deprecated request.
5. Missing, invalid, expired, malformed, or combined credentials cannot select an alternate deprecated handler path.
6. A supported alias or representation resolving to a deprecated class receives the same 404 outcome.
7. `EscalateAlarmRequest` and `TakeAlarmRequest` are blocked in both SHM and SHM ALM.
8. Supported non-deprecated request classes continue through their assigned authentication, authorization, validation, and business behaviour.

## UI/UX Rules

- No new UI is introduced.
- Current supported application workflows must not display an unexpected SMAR-2656 404, blank data, stuck loading state, false completion, or retry loop.
- Any observed current-client call to a Matrix M1 request is a release-blocking dependency requiring investigation.

## Validation Rules

- The exact route, method, headers, parameters, and valid body for each Matrix M1 request come from an approved legacy collection or developer endpoint mapping.
- Completely malformed transport data that prevents request-type resolution may follow the platform's existing malformed-request contract and is not evidence of deprecated-handler execution.
- OAuth variants are executed only for routes technically capable of entering OAuth dispatch; non-applicable variants require technical evidence.
- Exact status for resolvable deprecated requests is `404 Not Found`.
- The response body follows the approved standard not-found schema and exposes no stack trace, internal namespace, credentials, full payload, or protected client/health data.

## API / Backend Impact

- Legacy SHM dispatcher classification changes for 33 request classes.
- SHM ALM dispatcher classification changes for `EscalateAlarmRequest` and `TakeAlarmRequest`.
- Rejection occurs before handler start, business validation, and persistence.
- Active dispatcher registrations must remain available after service restart and across deployed instances.
- Exact routes and message discriminator mappings remain implementation-dependent and require approved evidence.

## Integration Impact

- Rejected alarm commands must not take or escalate an alarm.
- Rejected task, calendar, device, file-group, measurement, medication, notification, and registration requests must not produce their corresponding business mutation or downstream processing.
- Supported Portal, CP Web, Mobile, Carer App, IPD, AWS, and alarm consumers must continue using active non-deprecated routes.
- Exact queue, worker, notification, and provider names require runtime instrumentation and are not inferred.

## Permissions / Roles

- Deprecation is request-class based and is not bypassed by an otherwise authorized HMAC or OAuth caller.
- Existing roles, tenant restrictions, and resource authorization for supported non-deprecated requests remain unchanged.
- Responses must not reveal protected record existence or credential-validation details.

## Background Jobs / Queues

- A rejected deprecated request must not create or advance its associated business job or queue work.
- Supported active requests retain their currently approved queue and worker behaviour.
- Exact queue names, retry policies, and DLQ impact could not be verified from approved evidence.

## Audit / History / Logs

- Correlation or trace evidence must identify deprecated dispatch rejection and absence of deprecated handler start/completion.
- Rejected requests must not create a successful business-action history entry.
- Logs must not expose HMAC material, OAuth values, internal stack traces, full request bodies, or unnecessary client/health data.
- Supported state-changing control requests retain their established history and audit outcomes.

## Reports / Export Impact

- No direct report or export change is confirmed.
- Reports and exports must not reflect mutations from rejected deprecated requests.

## Cross-Platform Sync Impact

- Current supported clients must continue to load, update, and synchronize through active request classes.
- A deprecated request must not create a partial backend state that appears on another platform.
- Representative supported workflows must converge to the same final state after refresh or re-login.

## Privacy / Sensitive Data Impact

- Use synthetic non-production clients, files, devices, groups, alarms, tasks, medications, and notifications.
- Evidence must redact authentication material and unnecessary client, contact, device, tenant, and health information.
- The standard 404 response must not disclose resource existence, credential failure reason, internal type names, or full payload content.

## Test Data, Isolation, and Cleanup

- Use isolated STAG records and controlled alarm/notification recipients.
- Record baseline state before state-changing supported-control tests.
- Reset disposable alarms and test records without removing unrelated data or required audit evidence.
- Do not invoke real production alarm, call, message, or notification delivery.

## Regression Risk

High security risk if any deprecated class remains reachable. High safety and operational risk if shared classification blocks supported alarm or client workflows. High data-integrity risk if rejection occurs after handler entry. Medium compatibility risk if service instances deploy inconsistent classification or current clients still call Matrix M1 requests.

## Confirmed Decisions
