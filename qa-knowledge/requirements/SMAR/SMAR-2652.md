## Requirement Summary

Correct the CP Desktop Device Setup Steps dependency rules so Generate CAMS Asset depends on Assign To Client File instead of Generate Asset. The prerequisite and ordering rules apply to the selected main/parent device. Rejected add, delete, and reorder actions must leave the device configuration unchanged.

## Confirmed Scope

- CP Desktop: Settings → Device Setup Steps.
- Main/parent-device setup-step configuration.
- Add-step prerequisite validation for Generate CAMS Asset.
- Delete protection for Assign To Client File while Generate CAMS Asset exists.
- Ordering protection that keeps Assign To Client File before Generate CAMS Asset.
- Independent add, delete, and valid reorder behavior between Generate Asset and Generate CAMS Asset.
- Save, device-switch, reload, and false-persistence validation in the approved cases.

## Out of Scope

- No runtime Service Request, CAMS/INS asset creation, Client File association, API-validation, existing-data remediation, mobile, Portal, CP Web, billing, or reporting behavior is confirmed by the approved SMAR-2652 cases.

## Business Rules

1. Generate CAMS Asset can be added only when Assign To Client File already exists on the selected main/parent device.
2. Generate CAMS Asset must remain after Assign To Client File.
3. Assign To Client File cannot be deleted while Generate CAMS Asset exists.
4. Generate CAMS Asset may be deleted without deleting Assign To Client File.
5. Generate Asset and Generate CAMS Asset do not depend on one another for add or delete operations.
6. Reordering Generate Asset must not change the Assign To Client File → Generate CAMS Asset dependency.

## UI/UX Rules

- Invalid add, delete, and reorder actions display an error dialog.
- Deleting Assign To Client File while Generate CAMS Asset exists displays exactly: `Can't delete Assign To Client File. Remove the following steps first: Generate CAMS Asset`.
- Exact message text for invalid add and reorder operations remains an Open Question.
- A rejected action retains the original setup-step list and order.

## Validation Rules

- Dependency validation uses the latest state of the selected device: after Assign To Client File is added, Generate CAMS Asset can be added.
- Generate Asset must not be requested as a prerequisite for Generate CAMS Asset.
- Generate CAMS Asset must not prevent Generate Asset from being added, deleted, or moved to another valid position.
- Blocked add, delete, or reorder actions must not persist a partial configuration change.
- Saved valid configurations must remain attached to the correct main/parent device after switching away and returning.

## API / Backend Impact

Open Question. The approved evidence verifies CP Desktop configuration behavior and persistence but does not identify routes, handlers, contracts, or independent backend validation.

## Integration Impact

The approved cases verify Device Setup configuration persistence. Existing regression knowledge states that setup-only changes do not trigger notifications unless configured; no new FCM, SMS, email, Twilio, billing, or alert behavior is introduced by this requirement.

## Permissions / Roles

Approved delete and reorder cases assume a user with permission to manage Device Setup Steps. Unauthorized-user behavior is not specified.

## Regression Risk

- Device Setup add, delete, reorder, save, and reload flows on CP Desktop.
- Removal of the former Generate Asset ↔ Generate CAMS Asset dependency in both directions.
- Preservation of Assign To Client File → Generate CAMS Asset ordering when Generate Asset is moved.
- False-persistence checks after rejected actions.

## Confirmed Decisions

- DEC-002: Generate CAMS Asset must follow Assign To Client File; Assign To Client File deletion is blocked while the dependent step exists; Generate Asset is independent of Generate CAMS Asset.
