## Requirement Summary

SMAR-2421 adds **Establishment Fee** to the System, Village/Group, and Client File Billing Defaults hierarchy with a System default amount of **$14.42** and lower-level overrides. It adds the **Non-Recurring** Rate Type, locks Establishment Fee to that Rate Type, leaves Default Billing Type selectable, and changes Non-Recurring service-date editing to one **DATE** field whose selected value is persisted as both Start Date and End Date. Hardware Purchase is not migrated by this ticket.

The Jira phrase “monthly rate” is retained only as terminology history. Later confirmed comments and the current approved requirement establish **Non-Recurring** as the Rate Type; they do not remove the confirmed $14.42 default amount.

## Confirmed Scope

- CP Desktop Billing Defaults at System, Village/Group, and Client File levels.
- Establishment Fee service visibility, default amount, Rate Type lock, amount overrides, inheritance, and isolation.
- Existing and newly created Client Files using the confirmed hierarchy.
- Client File Village change when no File-level Establishment Fee override exists.
- Client File Billing Services date editing and grid evidence for equal Start Date and End Date.
- Targeted regression for Hardware Purchase and representative existing recurring services.

## Out of Scope

- Migrating or locking Hardware Purchase to Non-Recurring under SMAR-2421.
- Establishment Fee Billing Report and export coverage owned by related SMAR-2425 and consolidated parent SMAR-2395 work.
- Unsupported production billing, invoices, notifications, alarms, jobs, and queue processing.

## Business Rules

- The inheritance order is System → Village/Group → Client File.
- A lower-level Establishment Fee amount override does not change its parent or unrelated Villages/Client Files.
- Establishment Fee always uses Non-Recurring within this ticket.
- Default Billing Type is not locked by this change.
- A Non-Recurring Establishment Fee represents one service date, stored in both Start Date and End Date.

## UI/UX Rules

- Display **Establishment Fee** and **Non-Recurring** using the approved labels.
- Rate Type is read-only for Establishment Fee at System, Village, and Client File levels.
- Date editing shows one field labelled **DATE** and does not show separate **START DATE** and **END DATE** inputs.
- The existing Billing Services grid is not redesigned; where both date columns remain, both display the same persisted value.

## Validation Rules

- One valid date is sufficient to save a Non-Recurring Establishment Fee service date.
- Exact amount boundaries, decimal precision, blank/null handling, validation text, and override removal/reversion are not supplied and remain GAP-02.
