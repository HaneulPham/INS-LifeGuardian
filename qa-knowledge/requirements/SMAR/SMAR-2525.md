## Requirement Summary

Extend CP Desktop **Asset Management → Assets → Import Asset** so a CSV import can update an existing asset's Imei and Mac Address while preserving the existing new-asset creation path. Matching uses Barcode and the selected Asset Type. Invalid Asset Type, Imei, MacAddress, or file structure must not create or partially update the affected asset.

## Confirmed Scope

- CP Desktop Import Asset file selection, header validation, and row processing.
- Existing-asset matching by Barcode and selected Asset Type.
- New-asset creation when no match exists.
- Existing-asset Imei/MacAddress full and partial updates.
- Blank/whitespace handling and invalid-value non-mutation.
- Reopen/search evidence for persistence, duplicate prevention, and unrelated-field preservation.

## Out of Scope

- File-size limits; the reviewer confirmed that a `>20 MB` limit was not implemented and was outside this ticket.
- Same Barcode across different Asset Types; the reviewer cancelled the case because Asset Type barcode prefixes prevent that setup.
- Exact backend route, database object, audit event, and import telemetry where no approved evidence is supplied.
- Production data and production execution.

## Business Rules

1. Import processing identifies the target using the trimmed Barcode and selected Asset Type.
2. One existing match is updated in place; a second asset is not created.
3. Only Imei and Mac Address may change on an existing match.
4. A missing match preserves the existing create behavior.
5. A selected Asset Type mismatch is a validation failure, not a create fallback.
6. Both optional fields blank on an existing match means skip; one supplied valid field updates without clearing the other.

## UI/UX Rules

- The entry point remains **CP Desktop → Asset Management → Assets → Import Asset**.
- The tester must receive a visible invalid-file or invalid-row outcome when supported data validation fails.
- Exact message wording and row-versus-file presentation are not confirmed and must not be hardcoded.

## Validation Rules

- File header: exact fields `Barcode,Imei,MacAddress`; missing, renamed, or extra columns are rejected by the reviewed suite.
- Barcode is required for row targeting.
- Imei: optional; when supplied, exactly 15 numeric digits and Luhn-valid.
- MacAddress: optional; when supplied, six colon-separated hexadecimal pairs.
- Hyphen-separated, unseparated, short/long, or non-hex MAC values are invalid.
- Leading/trailing whitespace is removed before evaluation and is not persisted.

## Regression Risk

Updating a create-only importer can create duplicate assets, update the wrong Asset Type, clear an omitted identifier, or partially mutate an invalid row. Recheck existing asset creation, Asset Type/barcode relationships, multi-row isolation, current Asset Management search/detail, and consumers that rely on stable asset identity.
