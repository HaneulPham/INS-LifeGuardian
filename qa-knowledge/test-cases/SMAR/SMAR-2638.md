## Duplicate Review

- Existing related cases checked: SMAR-2658 `GetClientFileRequest` HMAC/OAuth compatibility.
- Partial overlap: G2-01 overlaps valid-HMAC compatibility; G2-06 and G2-07 both use cryptographically invalid signatures.
- Decision: Keep all approved IDs.
- Unique coverage: G2-01 proves the SMAR-2638 change does not break valid HMAC; G2-06 uses a wrong secret; G2-07 tampers with a generated HMAC while business identifiers remain unchanged.

## Shared Execution Controls

- Use synthetic QA clients, client files, devices, and correlation IDs.
- Use approved non-production HMAC material; never record credential values in this file or evidence.
- Confirm host, route, request serialization, HMAC/timestamp headers, signing algorithm, and rejection baseline before execution.
- Treat HTTP `401` as a non-normative reference until the Old Backend rejection contract is verified.
- Alarm tests require isolated recipients and cleanup that removes only controlled alarms while preserving required audit/security evidence.
