## Requirement Summary

The old backend exposed `GET /api/devices` without authentication and returned device identifiers. SMAR-2663 removes that route to close the documented information-disclosure vulnerability. Requests to the removed route return exact HTTP `404 Not Found` regardless of whether the caller supplies no credential or a valid credential, and the response exposes no device information or redirect to another device-data route.

QA directly verifies the approved Staging legacy instance only. The Jira ticket lists Production instances for deployment, but Jira comment 44495 explicitly excludes direct Production execution from the approved QA scope.

## Confirmed Scope

- `GET /api/devices` on the approved Staging legacy instance.
- An unauthenticated request with no authorization header, authentication cookie, API key, or other credential.
- A request using a valid non-expired credential supported by the Staging instance.
- Exact `404 Not Found` response verification.
- Response-body and redirect verification proving that no device data is disclosed.
- Redacted request and response evidence from the approved QA network or VPN.

## Out of Scope

- Direct requests to Production instances, per Jira comment 44495.
- Testing replacement device-listing APIs or supported authenticated device workflows.
- Broad vulnerability scanning, penetration testing, or unrelated old-backend routes.
- Performance testing; the ticket confirms no expected performance impact.

## Business Rules

1. The removed route returns `404 Not Found`; `401 Unauthorized` is not the accepted outcome.
2. Authentication state does not change the removed-route outcome.
3. The response must not expose a device list, device identifier, device property, record-existence detail, or redirect target that exposes device data.
4. No current end-user workflow is expected to depend on this route.

## UI/UX Rules

- No user-interface change is included.

## Validation Rules

- Capture the actual outgoing request to prove credentials were absent for the unauthenticated case.
- Prove the credential used by the authenticated case is valid through an approved protected control before calling the removed route.
- Do not accept `200`, another 2xx response, `401`, or a redirect as equivalent to the required 404.
- Treat any device identifier or property in the response as an information-disclosure failure.

## API / Backend Impact

- The legacy `GET /api/devices` route handler is removed.
- The network host can still receive the HTTP request, but no application route may serve the former device listing.
- Exact status is `404 Not Found` for both approved authentication contexts.

## Integration Impact

- No replacement integration or downstream trigger is confirmed.
- Existing supported device APIs and current end-user workflows are unchanged and are not exercised by the two approved cases.

## Permissions / Roles

- No credential and one valid authorized test credential are covered.
- A valid credential cannot reactivate or authorize the removed route.

## Background Jobs / Queues

- None confirmed. The endpoint is read-only and route removal must not create a job or queue message.

## Audit / History / Logs

- Tester-accessible evidence is the captured request, response status, response body, and redirect history.
- Internal route or handler logs are not required by the approved cases.
- Evidence must redact credential values and avoid storing unnecessary device, client, or health information.

## Reports / Export Impact

- None confirmed.

## Cross-Platform Sync Impact

- None confirmed for the removed direct endpoint.

## Privacy / Sensitive Data Impact

- The change closes unauthenticated disclosure of device identifiers and properties.
- Use synthetic non-production credentials and privacy-safe evidence.
- Do not store plaintext authentication material, production device data, client data, or health information.

## Test Data, Isolation, and Cleanup

- Execute only against the approved Staging legacy host from the approved QA network or VPN.
- Use an authorized synthetic test account for the authenticated case.
- The calls are read-only; no data cleanup is expected.
- Clear local API-client authentication defaults before the unauthenticated case and redact all captured credential material.

## Required Test Instrumentation

- API-client request capture showing the final URL, method, headers, response status, response body, and redirect history.
- An approved protected control proving the authenticated case's credential is valid without storing the credential value.

## Regression Risk

High security and privacy risk if any route, alias, redirect, or authentication context still returns device information. Low expected functional regression because Jira states that current end-user functionality does not use these old-backend endpoints.

## Confirmed Decisions

- DEC-017: Remove the route, return exact `404 Not Found` for unauthenticated and valid-authenticated requests, and execute direct QA only on Staging.
