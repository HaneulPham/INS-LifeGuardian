## Requirement Summary

Rename the current LGX dual-frequency device, asset, and stock-type descriptions to the confirmed VFII labels across CP Desktop and Portal Web while preserving existing reference identities, mappings, quantities, billing configuration, Service Request relationships, and report data.

## Confirmed Scope

- CP Desktop Settings: Devices, Device Setup Steps, listed reports/exports, and Billing Defaults.
- CP Desktop Asset Management: Asset Types, Assets, Stock Levels, and the approved create/receive-order stock-type selector.
- CP Desktop Devices and Client File device/asset views.
- CP Desktop Service Request grid, detail, Generate Asset, checklist, linked records, and supported print output.
- Portal Web Devices, Activation Report, and Low Usage Report.
- Reference-data/release-note deployment evidence for the asset-type description.

## Out of Scope

- New LGX device, asset, or stock-type business functionality beyond the rename.
- Mobile SOS and Mobile Carer because no affected label surface was supplied.
- Rewriting historical audit or change-log text until the product rule is confirmed.
- Direct production database manipulation by QA.

## Business Rules

- VFII is the dual-frequency model; VFI is not an interchangeable label.
- Current device and asset labels use `SmartHome LGX VFII`.
- Current stock-type labels use `SmartHome LGX VFII Dialler`.
- The rename must not create a second current reference-data option.
- Existing device, asset, stock, client-file, Service Request, setup-step, and billing relationships remain attached to the same records.

## UI/UX Rules

- Current-value grids, details, filters, selectors, reports, and exports show the applicable VFII label.
- Old DF and `LGX Dual Frequency` values do not remain available as active/current choices on confirmed surfaces.
- Search/filter by the new label returns the existing applicable records.

## Validation Rules

- Current type options appear once; old and new options are not duplicated.
- Renaming does not change stock counts, billing rates/cycles, linked client/device records, or checklist steps.

## API / Backend Impact

- The ticket changes reference-data descriptions consumed by UI and reports.
- The exact database object, API route, request schema, and deployment script are not supplied and must not be hardcoded in QA cases.

## Integration Impact

- Reports and exports consume the renamed device, asset, or stock-type descriptions while retaining source identifiers and row counts.
- No new third-party provider integration is confirmed.

- Portal Web: Activation and Low Usage reports.
- Output identifiers and row counts remain aligned with source device/asset records.

## Cross-Platform Sync Impact

- CP Desktop and Portal Web consumers converge on the same current device description for the same existing record.

## Privacy / Sensitive Data Impact

- Use synthetic or approved non-production device, asset, client-file, and Service Request records.
- Do not store client personal, medical, contact, authentication, or tenant-sensitive values in evidence.

## Test Data, Isolation, and Cleanup

- Use isolated LGX device/asset records with stable privacy-safe identifiers.
- Generated assets and Service Requests must be non-production test records and cleaned up through supported application workflows while preserving required audit evidence.
- Report/export evidence must redact unrelated client information.

## Required Test Instrumentation

- Developer- or operations-supported release-note and deployment evidence is required for R4.
- Final corrected-build evidence is required for the previously failing Stock Level report and Service Request detail paths.

## Regression Risk

Reference descriptions are shared by Settings, setup templates, Asset Management, client/device relationships, Service Requests, billing defaults, reports/exports, and Portal views. A partial deployment can leave inconsistent labels or broken mappings across consumers.

## Confirmed Decisions

- DEC-019 — VFII, not VFI, is the dual-frequency model label used by SMAR-2617.
